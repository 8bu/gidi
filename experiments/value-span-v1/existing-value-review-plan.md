## Escalation rule (predeclared)

- Error: the human value label differs from the proposal (span, or present versus null) or the human annotation_status is not 'complete'.
- (a) any error in a sampled stratum -> that stratum is expanded to full review (the scorer writes value-escalation-queue.jsonl).
- (b) Clean audit: 0-1 errors in the audit sample -> the auto-accepted clean set stands; >=2 errors -> stop; the clean auto-accepted population is reviewed in stages of 50 records (value-escalation-queue.jsonl).
- (c) Must-review: errors do not trigger escalation (expected); they are reported.
- (d) Unsampled: unsampled flagged records keep their rule proposal (status pending-stratum-check); they train only when the scorer marks their stratum passed, and are never human labels.

## Quet command

```sh
quet annotate datasets/annotation-v2/value-review-queue.jsonl \
  --schema configs/annotation-v2-value.quet.yaml \
  --out datasets/annotation-v2/value-labels.jsonl \
  --proposals datasets/annotation-v2/value-proposals.jsonl
```

`--out` is strict: labels must be ids of the queue. Proposals are advisory; only the
reviewer's confirmed decision is saved. Afterwards:

```sh
uv run python scripts/score_value_review.py --dataset existing-value-review
```

The scorer writes `experiments/value-span-v1/review-score.json` and, when the rule escalates, `datasets/annotation-v2/value-escalation-queue.jsonl` with its Quet command. `scripts/build_training_v2.py` refuses to run without a fresh score.
